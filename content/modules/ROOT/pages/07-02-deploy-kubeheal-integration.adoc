== What Gets Deployed

The KubeHeal integration overlay adds four resource groups to the `parasol-insurance` namespace without modifying the application itself:

[cols="1,2"]
|===
| Resource | Purpose

| **RBAC** (ClusterRole + RoleBinding)
| Grants the coordination engine in `self-healing-platform` permission to read pods, events, and services -- and to restart deployments -- in our namespace

| **ServiceMonitor**
| Tells Prometheus to scrape the {company-name} app's `/metrics` endpoint every 15 seconds

| **PrometheusRule**
| Defines alert rules: `ParasolOOMRisk`, `ParasolCrashLooping`, `ParasolCPUThrottling`, `ParasolDBConnectionFailure`, `ParasolDiskPressure`

| **NetworkPolicy + ConfigMap**
| Allows the {company-name} app to reach the platform's KServe InferenceService for LLM inference across namespaces
|===

== Get the repository

The commands in this section run from a checkout of the lab repository. The Showroom terminal does not include that checkout.

[source,terminal]
----
cd ~
if [ ! -d parasol-insurance/.git ]; then
  git clone --branch kubeheal-main --single-branch \
    https://github.com/KubeHeal/parasol-insurance.git
fi
cd parasol-insurance
git status -sb
----

The clone runs only when `~/parasol-insurance` is missing. You should end in that directory, and the status line should name `kubeheal-main`:

[source,terminal]
----
## kubeheal-main...origin/kubeheal-main
----

Stay in this directory for the rest of section 7. A new terminal needs `cd ~/parasol-insurance` before the later commands.

On a ROSA cluster that already runs the self-healing platform, deploy the application into this same namespace first:

[source,terminal]
----
oc apply -k bootstrap/rosa/
----

That creates Postgres, MinIO, and `ic-app` in `parasol-insurance`. `bootstrap/ic-shared-app/base/` targets `ic-shared-app` and waits for workshop namespaces this cluster does not have.

== Step 1: Apply the Integration Overlay

In a terminal, run:

[source,terminal]
----
oc apply -k bootstrap/kubeheal/
----

You should see one line per object. A first apply prints `created`. A second apply prints `unchanged`, or `configured` when the live object differed from the file. All three words are success.

[source,terminal]
----
serviceaccount/parasol-remediator unchanged
role.rbac.authorization.k8s.io/parasol-remediator unchanged
clusterrole.rbac.authorization.k8s.io/kubeheal-parasol-insurance-access unchanged
rolebinding.rbac.authorization.k8s.io/kubeheal-coordination-engine unchanged
rolebinding.rbac.authorization.k8s.io/parasol-remediator unchanged
clusterrolebinding.rbac.authorization.k8s.io/parasol-remediator-monitoring-view unchanged
configmap/kubeheal-kserve-config unchanged

----

== Step 2: Verify RBAC

Confirm that the self-healing platform's service account can now read pods in our namespace:

[source,terminal]
----
oc auth can-i get pods \
  --as=system:serviceaccount:self-healing-platform:self-healing-operator \
  -n parasol-insurance
----

[source,terminal]
----
yes
----

Try a write operation too:

[source,terminal]
----
oc auth can-i delete pods \
  --as=system:serviceaccount:self-healing-platform:self-healing-operator \
  -n parasol-insurance
----

[source,terminal]
----
yes
----

The coordination engine needs that permission to restart unhealthy pods.

== Step 3: Verify NetworkPolicy

[source,terminal]
----
oc get networkpolicy -n parasol-insurance
----

[source,terminal]
----
NAME                        POD-SELECTOR   AGE
allow-ic-app-to-claimdb     app=ic-app     6h1m
allow-parasol-to-platform   app=ic-app     6h1m
----

`AGE` will not match. Inspect both policies:

[source,terminal]
----
oc describe networkpolicy allow-parasol-to-platform allow-ic-app-to-claimdb -n parasol-insurance

Read that as separate egress paths from `ic-app`:

* DNS (ports 53 and 5353) to the `openshift-dns` namespace
* MinIO on port 9000, Milvus on port 19530, and the Qwen predictor on ports 8080 and 80
* Ports 8080 and 80 to the `self-healing-platform` namespace (KServe inference)
* Port 443 to any destination
* PostgreSQL on port 5432, only in `allow-ic-app-to-claimdb`

Kubernetes unions every NetworkPolicy that selects `ic-app`. The Postgres allow is its own object so section 7.4 can delete it. A second policy cannot take that path away while this one still exists.

== Step 4: Verify ConfigMap

[source,terminal]
----
oc get cm kubeheal-kserve-config -n parasol-insurance -o yaml
----

The object metadata is long. The `data` section should match this:

[source,terminal]
----
INFERENCE_SERVER_URL: http://anomaly-detector-stable.self-healing-platform.svc.cluster.local:8080/v1
MAX_TOKENS: 512
MODEL_NAME: anomaly-detector
PRESENCE_PENALTY: 1.03
TEMPERATURE: 0.01
TOP_P: 0.95
----

`INFERENCE_SERVER_URL` points at `anomaly-detector-stable` in `self-healing-platform`.

== Step 5: Confirm Application Health

Make sure the {company-name} application is still running normally:

[source,terminal]
----
oc get pods -n parasol-insurance
----

[source,terminal]
----

parasol-remediator-b799f858-gn4jl   1/1     Running     0          85m

Pod names and ages will differ. `ic-app`, `claimdb`, and `parasol-remediator` should be `Running`. `db-init-job` is `Completed`. `milvus`, `minio`, and `qwen-predictor` are the rest of this stack. The overlay does not restart the application pods that were already running.
