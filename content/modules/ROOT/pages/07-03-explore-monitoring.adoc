Now that the integration overlay is deployed, Prometheus is already scraping the {company-name} application's metrics. Let's see what it's collecting.

== Step 1: Check Monitoring Resources

[source,terminal]
----
oc get servicemonitor,prometheusrule -n parasol-insurance
----

Expected output:

[source,terminal]
----
NAME                                          AGE
servicemonitor.monitoring.coreos.com/parasol-insurance   2m

NAME                                                    AGE
prometheusrule.monitoring.coreos.com/parasol-insurance-alerts   2m
----

== Step 2: View Metrics in the {ocp} Console

. Open the {ocp} Console
. Navigate to **Observe** > **Metrics**
. In the query box, enter:
+
[source,promql]
----
container_memory_working_set_bytes{namespace="parasol-insurance", container!=""}
----
+
. Click **Run Queries**

You should see the memory usage for the `ic-app` and `claimdb` containers. Under normal load, `ic-app` uses approximately 150-200 MB.

Try another query to see CPU usage:

[source,promql]
----
rate(container_cpu_usage_seconds_total{namespace="parasol-insurance", container!=""}[5m])
----

== Step 3: Check Alert Rules

. In the {ocp} Console, navigate to **Observe** > **Alerting** > **Alerting rules**
. Search for `Parasol`

You should see four rules:

[cols="2,1,3"]
|===
| Alert | Severity | Condition

| `ParasolOOMRisk`
| Critical
| Memory usage > 85% of limit for 1 minute

| `ParasolCrashLooping`
| Critical
| Pod restarted > 3 times in 10 minutes

| `ParasolCPUThrottling`
| Warning
| CPU throttled > 25% of the time for 5 minutes

| `ParasolDBConnectionFailure`
| Critical
| Zero available replicas for the `claimdb` deployment for 1 minute
|===

All alerts should currently show as **Inactive** (green). We will change that in the next section!
