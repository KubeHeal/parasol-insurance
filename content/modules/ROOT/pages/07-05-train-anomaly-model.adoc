The self-healing platform ships with a baseline anomaly detection model, but we can do better. By training a model specifically on the {company-name} application's metrics, we get a detector that understands what "normal" looks like for _our_ workload.

== The Algorithm: Isolation Forest

We are using **Isolation Forest** -- the same unsupervised anomaly detection algorithm used in the platform's core detector. It works by randomly partitioning data: anomalies are isolated in fewer splits than normal points.

The model is packaged as an **sklearn Pipeline** (StandardScaler + IsolationForest) so it can be served directly by KServe's sklearn server.

== Step 1: Open the Training Notebook

In the platform workbench (`self-healing-workbench` in `self-healing-platform`), open:

[source,text]
----
lab-materials/07/07-05-train-anomaly-model.ipynb
----

== Step 2: Run the Notebook

Execute each cell in order. The notebook will:

. **Configure** the data source (synthetic by default, or Prometheus if the app has been running)
. **Generate synthetic data** that mimics the five chaos scenarios you just ran:
** OOM risk (high memory near limit)
** CPU spike (sustained high CPU)
** Crash loop (high restart count, low CPU/memory)
** Network partition (very low network I/O)
** Disk pressure (elevated memory + high network TX)
. **Engineer features** including derived metrics:
** `memory_utilization` = memory_usage / memory_limit
** `network_ratio` = network_tx / network_rx
** `cpu_memory_product` = cpu_usage x memory_utilization
. **Train the Isolation Forest** with 200 estimators and 10% contamination rate
. **Evaluate the model** -- you should see an F1 score above 0.6 (the quality gate)
. **Save the model** as `model.pkl` with training metadata

== What We Built

[cols="1,2"]
|===
| Component | Details

| **Algorithm**
| Isolation Forest (sklearn)

| **Pipeline**
| StandardScaler -> IsolationForest

| **Features**
| 9 (cpu_usage, memory_usage, memory_limit, restarts, network_rx, network_tx, memory_utilization, network_ratio, cpu_memory_product)

| **Training data**
| 5000 synthetic samples mimicking the 5 chaos scenarios

| **Output**
| `model.pkl` ready for KServe serving
|===

This model can now be deployed as a KServe InferenceService. The coordination engine sends it a feature vector and the model returns `1` (normal) or `-1` (anomaly), driving the self-healing decision.
